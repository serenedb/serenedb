Below is a collection of tips to help when attempting to import complex CSV files. In the examples, we use the <a href="/files/docs/flights.csv" download>`flights.csv`</a> file.

## Override the Header Flag if the Header Is Not Correctly Detected

If a file contains only string columns the `header` auto-detection might fail. Provide the `header` option to override this behavior.

<SqlLogicTest id="data_import_and_export/csv/tips/example_001" />

## Provide Names if the File Does Not Contain a Header

If the file does not contain a header, names will be auto-generated by default. You can provide your own names with the `names` option.

<SqlLogicTest id="data_import_and_export/csv/tips/example_002" />

## Override the Types of Specific Columns

The `types` flag can be used to override types of only certain columns by providing a struct of `name` → `type` mappings.

<SqlLogicTest id="data_import_and_export/csv/tips/example_003" />

## Use `COPY` When Loading Data into a Table

The [`COPY` statement](../../sql/statements/copy/index.md) copies data directly into a table. The CSV reader uses the schema of the table instead of auto-detecting types from the file. This speeds up the auto-detection, and prevents mistakes from being made during auto-detection.

<SqlLogicTest id="data_import_and_export/csv/tips/example_004" />

## Use `union_by_name` When Loading Files with Different Schemas

The `union_by_name` option can be used to unify the schema of files that have different or missing columns. For files that do not have certain columns, `NULL` values are filled in.

<SqlLogicTest id="data_import_and_export/csv/tips/example_005" />
